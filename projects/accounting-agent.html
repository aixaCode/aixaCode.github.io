Architecture case study

AI Accounting & Company Records

I built a private, folder-first system for company and personal financial records. The important part is that the records remain understandable and useful without this application, a database or a particular AI provider.

Python / original PDF, CSV and XLSX evidence / portable JSON and Markdown / deterministic accounting rules / AI-assisted document reading / reproducible reports / Proxmox LXC

AI
Internal/private system. Implementation details are based on local project code.All projects

Overview

This started as a way to reconcile statements and invoices without handing accounting decisions to a model. It has grown into an internal company-management workspace covering multiple legal entities and their owners.

I eventually realised the organised folder was the product. Original documents remain the evidence; Markdown and versioned JSON preserve context and extracted records; deterministic Python handles statement parsing, FX conversion, categorisation, reconciliation, P&L and supported tax estimates. Dashboards and reporting packages are useful views, but I should be able to throw them away and rebuild them.

The boundary around AI is deliberate. I use it to read untidy documents, extract metadata, suggest matches and help review exceptions. I do not let it own accounting state or quietly turn a suggestion into a financial fact. The personal assistant receives only a privacy-safe, read-only summary.

Requirements

DurabilityRecords remain readable without the application, a database, chat history or a particular model provider.
TraceabilityEvery reported figure leads back to source files, deterministic rules and approved corrections.
IsolationEach company, accounting period and person's tax records stay separate by default.
PrivacyPrivate evidence and generated outputs stay outside Git; the assistant receives only aggregate JSON.

Architecture

I keep the evidence authoritative and make everything else rebuildable.

Files, schemas and documented commands remain usable by different authorised agents

The model helps me interpret evidence. Files, schemas and deterministic commands preserve the record independently of a model session.

I start with the legal entity, not the document type. Each company owns its records, each period has separate evidence and generated output, and personal tax never enters company calculations. If I add a combined management view, it must read separate summaries without blurring entity, currency, period or source.

Implementation detail

The implementation choice I care about most is lossless intake. Every file gets a SHA-256 identity and inspection record before it moves. I check canonical originals for byte-identical duplicates, validate archives against path traversal, and send uncertainty to a named review state rather than guessing a destination.

manifest = {
  document_id: `sha256:${digest}`,
  original_name,
  inspection,
  extraction,
  status,
  history
}

journal("planned", source, destination, digest)
atomic_move(source, destination)
journal("complete", source, destination, digest)

Portable JSON writes go through a same-directory temporary file, fsync and atomic replacement. Rollback re-hashes the filed document before moving it. I would rather stop with a visible inconsistency than restore different bytes under an old identity.

Interesting engineering problems

  • Where should AI stop? AI extracts fields, suggests matches and reviews exceptions. It does not compute totals, categorise the ledger or quietly approve an interpretation.
  • How do you convert currency without an FX feed? Month-level rates are derived from the statements' own conversion rows; missing months fall back to the latest prior rate, then to an explicit configured approximation — never a silent guess.
  • How do you keep AI cost and drift low? The matcher asks only about uncached transactions, caps each prompt at 25 charges and merges successful chunks. A timeout leaves only that chunk for a later retry.
  • How do you fix mistakes without corrupting state? Corrections are deterministic file moves and cache-key migrations, with duplicate and bundled charges detected by exact arithmetic — hand-editing the caches is never the fix.
  • How do you avoid quiet finance errors? Extracted metadata retains provenance, JSON writes are atomic, estimates are versioned and data-quality checks suggest instead of mutate.
  • How do agents use the data safely? The personal assistant mounts a single aggregate summary read-only, so it can answer finance questions without access to statements or invoice PDFs.
  • How do you add another company without applying the wrong rules? Entity profiles gate period assignment, statement formats and calculation capabilities. Filing can remain enabled while unsupported bookkeeping or tax logic fails closed.
  • How do you keep shared records complete without losing identity? Intercompany evidence is copied only where each entity needs a complete record; SHA-256 comparison verifies byte equality and conflicts are never overwritten.

Trade-offs

Lessons learned

  • AI is useful for reading untidy documents. It should not quietly turn a suggestion into an accounting decision.
  • I trust small, inspectable scripts more than a general agent with broad permissions.
  • The durable product is the organised evidence and its contracts. The dashboard is useful, but it is still only a view.
